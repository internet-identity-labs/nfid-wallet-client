# Spec: Remove the legacy @dfinity/\* peer dependencies

> Status: APPROVED
> Created: 2026-09-22

## Overview

`package.json` pins four packages the repository's own code never imports:

```
"@dfinity/agent": "1.0.1",
"@dfinity/candid": "1.0.1",
"@dfinity/identity": "1.0.1",
"@dfinity/principal": "1.0.1",
```

They were added in `05225b304` alongside `@nfid/vaults@0.0.4-alpha.10`, whose
`peerDependencies` name all four. Yarn 1 does not install peer dependencies, so they had to
be declared by hand. Every source file in `apps/` and `packages/` is on `@icp-sdk/core` 5.4.0
instead, which is the successor of the same library — so the bundle currently ships two
copies of the agent, candid, identity and principal implementations.

Replace the four packages with webpack aliases onto the `@icp-sdk/core` subpath exports, the
same technique `apps/nfid-demo/webpack.config.js` already uses for `@nfid/embed`.

## Scope

- `package.json` — drop the four dependencies
- `yarn.lock` — regenerated by `yarn install`
- `apps/nfid-frontend/webpack.config.js` — add the four aliases
- `tsconfig.base.json` — add matching `paths` so TypeScript resolves the types in
  `@nfid/vaults`' `dist/index.d.ts`
- `packages/integration/src/lib/nfid-vaults/nfid-vaults.service.ts` — drop the now-pointless
  `as never` cast
- Out of scope: `apps/nfid-demo/webpack.config.js` (already aliases these), `@dfinity/utils`
  (a different package, already on `@icp-sdk/core ^5`), `@dfinity/cbor` (transitive)

## What the SDK actually needs

`@nfid/vaults@0.0.4-alpha.10`, `dist/index.mjs`:

```js
import * as Agent from "@dfinity/agent";
import { HttpAgent } from "@dfinity/agent";
...
const agent = new HttpAgent({ host: "https://ic0.app", identity });
return Agent.Actor.createActor(idlFactory, { canisterId, agent });
```

Runtime surface is two symbols — `HttpAgent` and `Agent.Actor` — both exported by
`@icp-sdk/core/agent`. `idlFactory` is written as `({ IDL }) => ...`, so the `IDL` namespace
comes from whichever agent builds the actor; no direct dependency on `@dfinity/candid`.

Type surface is `Identity` (from `@dfinity/agent`) and `Principal` (from
`@dfinity/principal`) in `dist/index.d.ts`. The `Identity` interface is declared identically
in `@dfinity/agent@1.0.1` (`lib/esm/auth.d.ts:35`) and `@icp-sdk/core@5.4.0`
(`lib/esm/agent/auth.d.ts:35`):

```ts
export interface Identity {
  getPrincipal(): Principal
  transformRequest(request: HttpAgentRequest): Promise<unknown>
}
```

`@dfinity/candid` and `@dfinity/principal` are peer dependencies of `@dfinity/agent@1.0.1`
itself; `@dfinity/identity` appears in the manifests of `@nfid/vaults` and `@nfid/embed` but
in neither bundle.

## Mapping

| Removed              | Alias target              |
| -------------------- | ------------------------- |
| `@dfinity/agent`     | `@icp-sdk/core/agent`     |
| `@dfinity/candid`    | `@icp-sdk/core/candid`    |
| `@dfinity/identity`  | `@icp-sdk/core/identity`  |
| `@dfinity/principal` | `@icp-sdk/core/principal` |

## Edge Cases

- `@nfid/vaults` builds its own `HttpAgent` with `host: "https://ic0.app"` hardcoded. That is
  true before and after this change; aliasing only swaps which implementation is constructed.
- After the swap, the agent validating certificates for vault calls is 5.4.0 rather than
  1.0.1. The identity handed in was already a `@icp-sdk/core` one, so the version mismatch
  across the `transformRequest` boundary goes away rather than appearing.
- `packages/integration/src/lib/nfid-vaults/nfid-vaults.service.ts:249` casts
  `identity as never` because the two `Identity` types were nominally distinct. With the
  `paths` entries they are the same declaration, so the cast goes and the comment above it
  becomes wrong — both are updated. This is not scope creep: without `skipLibCheck` doing the
  hiding, leaving the cast would silently keep the argument unchecked.
- Jest needs no mapping — no test imports `@nfid/vaults`.

## The paths entries must not carry a file extension

`apps/nfid-frontend/webpack.config.js` registers `TsConfigPathsPlugin`, which reads the same
`paths` map, and its `extensions` list is `[".js", ".ts", ".jsx", ".tsx"]`. It resolves before
`resolve.alias` is consulted, so a `paths` target ending in `.d.ts` hands webpack a
declaration file and the build dies:

```
ERROR in ../../node_modules/@icp-sdk/core/lib/esm/agent/index.d.ts 105:14
Module parse failed: Unexpected token (105:14)
> export { type ExpirableStore } from './utils/expirableStore.ts';
```

Written without an extension, webpack picks `index.js` and TypeScript picks `index.d.ts`.

## Out of Scope

- Upgrading `@nfid/vaults` past `0.0.4-alpha.10`.
- Touching `@dfinity/utils`, `@dfinity/cbor`, or `apps/nfid-demo`.
