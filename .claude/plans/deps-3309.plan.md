## Spec

- Bumps: `@wdio/{allure-reporter,cli,cucumber-framework,globals,local-runner,spec-reporter,types}` and
  `webdriverio` 9.31.x → 10.2.0; `expect-webdriverio` 7.0.1 → 8.1.0; `eslint-plugin-wdio` 9.31.3 → 10.2.0;
  `geckodriver` 7.0.0 → 8.0.0. Engines: all satisfied by Node 22.23.5. Only `apps/nfid-frontend-e2e` is affected.
- Intended behaviour: no functional change; the E2E suite behaves as on wdio 9.
- Breaking changes that hit us (release notes: https://github.com/webdriverio/webdriverio/releases/tag/v10.0.0):
  1. Element types: awaiting `$()` now yields `WebdriverIO.Element`, which is no longer assignable to
     `ChainablePromiseElement` → 3× TS2345 in `src/steps/activity.ts:54,68` (via
     `Activity.rowDate/rowActionType(row: ChainablePromiseElement)` in `src/pages/activity.ts:31,35`) and
     `src/steps/commonWalletSteps.ts:61` (local `clickWithWait(element: ChainablePromiseElement)` given
     `await Assets.tokenOptionsButton()`). Fix: widen those three parameter types to
     `ChainablePromiseElement | WebdriverIO.Element` (both types have `.selector`, `.$`, `waitForClickable`, `click`).
  2. #15684 "make `$` strict and throw on multiple matches" (`strictSelectors`, default `true`). Runtime only,
     tsc can't see it. Our pages use `$()` with selectors that match several elements, e.g.
     `$("#activity-table tr")` in `src/pages/activity.ts:5`; there are ~9 page files with `$()` calls and
     no way to audit them all statically. Fix: `strictSelectors: false` in `wdio.conf.ts` (keeps v9
     semantics; `wdio-mobile.conf.ts` inherits it via `Object.assign({}, desktopConfig, …)`).
     Adopting strict selectors per page is a separate follow-up, not part of this bump.
  3. Checked, **not used** by us: `executeAsync`, `switchToFrame`, `uploadFile`, `touchAction`, `throttle`,
     multiremote APIs, `MultiremoteConfig`, `setupExpect`, `react$`. Cucumber 13 comes inside
     `@wdio/cucumber-framework`; our steps import only from `@wdio/cucumber-framework`.
- Third-party blocker: `wdio-video-reporter@6.2.0` (latest; used in `wdio.conf.ts` and `wdio-mobile.conf.ts`)
  depends on `@wdio/reporter@^9`, `@wdio/globals@^9` → yarn installs a nested wdio 9 under it
  (`incorrect peer dependency "webdriverio@^9.28.0"`). Options:
  - **keep** and verify that the local E2E run still produces videos and doesn't crash — **recommended**
    (no code change; a reporter receives plain event objects, likely fine across majors);
  - drop it from both configs (lose CI videos) — fallback if the local run shows it broken (deviation);
  - replace — no maintained wdio 10 video reporter found.
