## Spec

- Bumps: `nx` + `@nx/{eslint,eslint-plugin,jest,js,react,storybook,webpack}` 23.2.1 → 24.0.6.
- Intended behaviour: no functional change. `nx build|serve|test|lint|storybook <project>` and
  `nx run-many -t …` keep working with the same flags CI uses (`--runInBand`, `--maxAttempts`,
  `--configuration=production|example`); the built bundles and the E2E suite behave as before.
- Breaking changes that hit us (Nx 24, `migrations.json` of each package):
  - `@nx/eslint:lint`, `@nx/jest:jest`, `@nx/storybook:{storybook,build}`,
    `@nx/webpack:{webpack,dev-server}` executors **removed** — used by every `project.json`
    (only `@nx/js:tsc` survives). PR suite: lint/test/build all fail with `Unable to resolve @nx/…`.
  - `composePlugins` / `withNx` (`@nx/webpack`) and `withReact` (`@nx/react`) are now **inert
    stubs** — `apps/nfid-frontend/webpack.config.js`, `apps/nfid-demo/webpack.config.js`. They
    would silently produce an empty base config (no entry, loaders, html, assets).
  - Nx's own `nx migrate --run-migrations` is now an AI-orchestrated run that commits each step
    by itself — not used. Its converters were run in a throwaway probe worktree for reference:
    eslint/jest/storybook converted the libraries cleanly; the two apps and `ui-tailwind-core`
    were left broken; the webpack converter can't detect our `.cjs` → ESM bridge.
- Approach (Nx's target model): inferred targets from plugins in `nx.json`
  (`@nx/eslint/plugin`, `@nx/jest/plugin`, `@nx/storybook/plugin`, `@nx/webpack/plugin`);
  `project.json` keeps only `@nx/js:tsc` builds, per-project option overrides and empty
  `production` / `example` configurations (so `--configuration=…` from release CI and
  `build:example` still resolve). Webpack configs become plain webpack configs:
  `NxAppWebpackPlugin` (options moved from `project.json`) + `NxReactWebpackPlugin` + a small
  local plugin that runs our existing tweaks (svgr split, babel/source-map excludes,
  autoprefixer removal, aliases, fallbacks, Define/Provide/CSP) on the final config.
  `optimization`/`sourceMap`/`extractLicenses` follow `NX_TASK_TARGET_CONFIGURATION`, as the
  executor configurations did.
- New dependency (beyond Dependabot's bump — **needs explicit OK**): `webpack-cli` 7.3.1
  (devDependency, exact pin). The inferred `@nx/webpack/plugin` targets run `webpack-cli`;
  it's an `@nx/webpack` 24 peer (`^5 || ^6 || ^7`), peers `webpack ^5.101` (we have 5.112.2).
- Removed: `storybook` / `build-storybook` targets of `nfid-wallet-client` — their `configDir`
  (`apps/nfid-frontend/.storybook`) doesn't exist, so they were already broken on `main`.
- Third-party blockers: none (peers of all 8 packages match our pins; no new peer warnings).

## Deviations

All within the files listed above (no new files):

- `apps/*/package.json`: also removed the `serve` script (`npm start` → `nx serve`), which would
  shadow the inferred `serve` target and loop.
- `lint` is an explicit `nx:run-commands` eslint target in **every** `project.json`, and
  `@nx/eslint/plugin` is not registered in `nx.json`. The plugin runs `eslint .` from the
  project dir, which shifts the base path of the root config's `files:` globs: the root rule
  `files: ["packages/ui/**/*"] → enforce-module-boundaries: off` stopped matching and `ui:lint`
  failed with 183 `ui ↔ nfid-wallet-client` circular-dependency errors (pre-existing cycle via
  `frontend/*` imports, hidden by that override). The explicit targets run from the workspace root
  like the old executor (`eslint --config packages/<p>/eslint.config.js packages/<p>`; apps and
  `ui-tailwind-core` use the root config) — same warning counts per project as `main`.
- `apps/*/webpack.config.js`: `commonChunk: false` (the old pipeline emitted no `common.js`; the
  production file list is now identical to `main`'s) and no `devServer.hot` in the raw config
  (webpack-dev-server defaults it to true; setting it makes `NxReactWebpackPlugin` add React
  Refresh, which the old setup never had and which needs a package we don't install).
- `apps/*/project.json`: explicit build `outputs` — the webpack plugin can't read `output.path`
  from our ESM config at graph time and inferred `outputs: []`, which would break cache restores.
- `packages/ui/.storybook/main.ts` not touched (the Nx converter's edit there was a no-op block).
